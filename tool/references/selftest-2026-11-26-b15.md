# B15 门禁小结 —— F5「终态口径」改为 done（2026-11-26）

本批只做一件事：**把 B13 真链暴露的 F5 修掉** —— 链跑完写 `status=done`，`blocked` 只留给真正卡住。
口径由人拍板（`done` + **不动启动器生成的 prompt**），收尾仍按家规 `selftest → publish → refresh-manifest`。

---

## 1. F5 根因与拍板口径

B13 真链跑完两个阶段后，台账终态是 `status=blocked` / `current_stage=3` / `max_stages=2`，
notes 原文 `current_stage 3 > max_stages 2 -> status=blocked, no next link spawned`。
链**成功跑完**却被记成故障，启动器自己的闸门却把 `status=done && current_stage >= max_stages` 认作
`chain_exhausted`（exit 3）—— 装置内部两套语义互相矛盾。

拍板结果：

1. **终态 = `done`**：全部阶段完成 ⇒ `status=done`，`current_stage > max_stages` 是完成信号，不是故障。
2. **`blocked` 只留真卡住**：人工验收 / 缺权限 / 无进展 / `blocked_on` 有未结项。
3. **不改 prompt**：只改家规块 + 台账种子 + 协议 ⇒ B10 的「mcode prompt 逐字不变」硬约束继续成立。

## 5. 遗留与下一批候选

1. **闸门不自动置 done**：子环若彻底漏掉收尾回写，台账会停在 `status=running`。按 B14 的教训，正解是
   「加机制兜底」（如阶段全 done 时闸门拒绝非 done 的 `next_session_id`）——超出本批拍板半径，交人决定。
2. **`protocol\practilog-agents-pointer.md:11`** 仍是旧口径（见 §2）。它不进发布清单；若今后被当作协议入口，
   需一并改。
3. **`tool\SKILL.md:139`** 的启动器闸门描述写「台账 blocked 或耗尽 ⇒ 拒绝起链」，而代码判据是
   `status=done && current_stage>=max_stages`。语义不算错（耗尽 = done），但措辞没提 done，可顺手对齐。
4. **真链复测**：本批只有装置级证据，没有真起一条链跑到终态。要坐实「跑完写 done」仍需一次真链（人工验收点）。
