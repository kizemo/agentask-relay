判据要点（三条是本轮踩出来的口径，别改回去）：

1. **闸门锁与链锁分开数**：链锁真实路径是 `docs\relay\.relay.lock`，`-Filter '*.lock'` 会把它误算进
   「陈旧锁未清」；断言只匹配 `*ledger.lock*`。
2. 任何 `commit` 断言前**必须先 `-Action status` 取 sha**，否则 CAS 直接判死、断言变假红。
3. `stage_fields` 缺 `stage_done` ⇒ **`exit=2` 用法错**；`rule_rewrote_existing_entry`（`exit=3`）只是纵深防御
   后盾，正常意图层走不到，不要拿它当主判据。

## 6. 已知限制（有意不扩面，不是缺陷）

1. 闸门**不校验** `current_stage <= max_stages` —— 该判据属 `start-relay.ps1` 的台账闸门。
2. `LEDGER_STATE` 输出**无** `blocked=` 计数。
3. 无实质变化的 patch 仍会刷新 `updated_at`，导致 sha 变化（幂等性靠 `*_append` 去重保证，不靠 sha 不变）。
4. 写锁只串行化**闸门提交**，**拦不住裸 `Set-Content`**；裸写的行会在下一环 CAS 时被判定冲突（实测 `exit=3`），
   即「事后判死」而非「事前阻止」。文档一律按此口径写，不写成「已彻底禁止裸写」。
5. `session_create` 真起链仍是人工步骤（`MANUAL_STEP real_session_activation`），自测**永不**调用它。

## 7. 本轮工具坑（写进 HANDOFF 的同源事实）

- **PowerShell 内联锚点补丁器改 Markdown 会静默失败**：打印了 `patched` 但盘上 sha 仍是旧基线、grep 不到新关键词，
  `throw` 前置守卫也没触发。⇒ 任何补丁后**必须 grep 盘上实测**，不得信 echo；改 Markdown 一律走 `edit` 工具。
- **锚点不得凭记忆写**（`HANDOFF.md` 后续候选编号真实为 `1..10` + 行 104 遗留重复 `7.`）。
- **`.ps1` 纯 ASCII** ⇒ `start-relay.ps1` 里的闸门配方文案用英文 + 反斜杠路径，不要塞 CJK（`ps1_ascii_bom_parse` 会红）。
- 两份 `AGENT-RELAY.md`（`protocol\` 与 `tool\templates\`）是 CJK Markdown，**不受家规 4 的 ASCII 约束**（只约束 `.ps1`），
  但必须保持 LF / 无 BOM（实测 `CR=0 BOM=False`）。
