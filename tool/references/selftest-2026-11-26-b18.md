## 1. B18-a 命名真断言（case 23，+9 条）

### 问题

B17 把链接命名改成零填充短横线风格（`relay-01of02`），但**只改了模板、没加断言**：
那串字符只存在于纯文本里，改回旧式（`relay-1-<stage>`）不会有任何一条用例变红。

### 做法：读「生成物」而不是抄「字符串」

新 case 23 跑**真实启动器**（`start-relay.ps1`，非 `-DryRun`）生成
`docs\relay\next-relay-prompt.txt`，然后在**产物**上断言：

| 断言 | 判据 |
|---|---|
| `link_naming_claude-code_uses_zero_padded_form` | 产物里 `relay-\d{2}of\d{2}` 命中 > 0 |
| `link_naming_claude-code_has_no_legacy_form` | 产物里旧式 `relay-\d+-` 命中 **0** |
| `link_naming_mcode_uses_zero_padded_form` / `..._has_no_legacy_form` | 同上，mcode 运行时 |
| `link_naming_cli_header_names_the_link` | CLI 产物含 `RELAY_LINK=relay-\d{2}of\d{2}` |
| `link_naming_cli_handoff_names_next_link` | CLI 产物含 `change RELAY_LINK=relay-01of02 to RELAY_LINK=relay-02of02` |
| `link_naming_rule_rejects_legacy_sample` | 旧式样本 `relay-1-inventory` **不满足**新正则（套件内鉴别力） |

### 套件外鉴别力（变异实验）

`reports\b18-naming-mutation.ps1`：把 TEMP 副本里 `start-relay.ps1` 的 `$linkTag/$nextLinkTag`
变异回旧式（先断言锚点唯一），再跑同一套断言：

- 基线：`BASELINE exit=0 new_form_hits=5 legacy_hits=0`
- 变异体：`MUTANT exit=0 new_form_hits=0 legacy_hits=1`
- 结论：`MUTATION_VERDICT=ASSERTION_HAS_TEETH`（改回旧式必红）

## 3. B18-c `chain_at_stage_cap`：验到了，还修掉了「说假话」

### 验（真实装置 + 真实台账，不是手改台账）

`reports\b18-cap-probe.ps1`：真实启动器起链 → 真实台账 → `relay-lock.ps1 -Action release` →
`relay-ledger.ps1 -Action status` 取在盘 sha256 → 提交 patch `{"bump_current_stage": true}`（CAS 走闸门）
→ `LEDGER_CAS_OK` / `current_stage 1->2` → 再次起链 `exit=3 reason=chain_at_stage_cap`。

- Part 1：`FAIL reason=chain_at_stage_cap current_stage=2 max_stages=2`（**受管写闸门注入**，不是伪造脏台账；
  装置自己拒绝，理由自洽）。
- Part 2：单阶段链（`MaxStages=1`）bootstrap 后 `current_stage=1 max_stages=1` 即触顶，
  第二次起链被拒 —— 但 HINT 仍写「every declared stage is done but status is still running」，
  阶段根本没跑。实测 `PART2_HINT_CLAIMS_ALL_DONE=True` ⇒ **文案在说假话，而且建议错误地 `set_status=done`**。

### 修（reason 不变，HINT 分形态）

改动点：`tool\templates\start-relay.ps1` 触顶分支（同步 `device\start-relay.ps1`，逐字一致）。

- FAIL 行补两个机器可读字段：
  `FAIL reason=chain_at_stage_cap current_stage=N max_stages=M stages=<id:status,...|none> all_done=<true|false|unknown>`
- HINT 按形态三选一（reason 白名单不变，`chain_at_stage_cap` 仍是既有集合）：
  1. `HINT=all_stages_done_but_status_running` —— 全 done，只是没人翻终态 ⇒ 可以 `{"set_status":"done"}` 收尾；
  2. `HINT=stage_cap_reached_with_open_stage` —— 还有阶段没跑 ⇒ **禁止**收尾，先把该阶段跑完或解卡；
  3. `HINT=stage_cap_reached_with_no_stage_records` —— 台账一条阶段记录都没有，完成性无法证明 ⇒ 先补记录。

同步的文档：`tool\templates\AGENT-RELAY.md` 与 `protocol\AGENT-RELAY.md`（闸门表第 229 行，**两份逐字一致**）、
`tool\SKILL.md`（四道闸门第 2 条）。

### 判别力（case 24，+18 条断言）

新 case 24 对三种形态各起一次真实启动器（`-DryRun`，闸门在取锁之前拒绝），逐条断言：
拒绝（`exit=3`）、`stages=` 摘要、`all_done=` 状态、HINT 归属、**HINT 互斥**，
外加一条否定断言「open_stage 形态里**不得**出现 `{"set_status":"done"}` 收尾建议」。

> 套件外鉴别力：`reports\b18-cap-hint-mutation.ps1` —— 把 TEMP 副本的闸门分支变异回旧版
> （单条「所有阶段都做完了」的 HINT），断言新用例必红、其余用例不受影响。
> 实测：`MUTANT_EXIT=1`、`SUITE_END pass=268 fail=10`，**10 条失败全是 `cap_hint_*` 新断言**，
> `OTHER_FAILS=0`（连 case 22 的 `gate_refuses_running_chain_at_stage_cap` 仍绿 —— 变异体照样 `exit=3` + 同 reason），
> `MUTATION_VERDICT=ASSERTION_HAS_TEETH`。
>
> ⚠ 探针自己踩过一次坑（已修）：替换块用 here-string 拼，而 PowerShell 的 here-string **不含结尾换行**，
> 导致分支自己的 `exit 3` 被粘进字符串，变异体变成「打印 FAIL 后继续跑、退出码 0」——
> 探针据此报 `ASSERTION_IS_WEAK`，正是这条自检把它抓出来的。现在替换前显式补换行，
> 并断言 `(?m)^    exit 3$` 仍在。

## 7. 本轮工具坑（新增）

26. **`current_stage` 是「下一个要跑的阶段号」，不是「已跑完的阶段数」**：台账 bootstrap 后就是 `1`，
    每完成一个阶段才 `+1`。所以 `current_stage >= max_stages` 命中的是「最多只剩一个阶段」，
    **不等于**「所有阶段都跑完了」—— 这正是 B18 修掉的那个说假话的根因。
    终态判据要等 `status=done` 且 `current_stage > max_stages`（本批真链：`3 > 2`）。
27. **判「某个阶段还没跑」不能只看 `current_stage`**：要看 `stages[]` 里每个阶段的 `status`；
    台账里 `stages=@()` 表示**一条阶段记录都还没有**（bootstrap 就是这样），
    这与「有阶段但还没跑」是两种形态，HINT 不能混着说。
28. **变异实验的锚点唯一性判据要看清「同类锚点有几处」**：`exit 3` 在启动器里每个闸门分支都有，
    对它做「全文唯一」判据会误报；正确做法是断言**替换区间**的内容特征
    （区间里必须含三个新 HINT token 与 `all_done=`），而不是断言区间终点全文唯一。
29. **真链会话的锁要显式转交**：`start-relay.ps1` 起的锁 holder 是 `start-relay:<pid>`，
    子会话接手要 `relay-lock.ps1 -Action adopt -SessionId <sid>`；否则子环跑完后锁一直占着。
30. **PowerShell 的 here-string 不含结尾换行**：`@'...'@` 的值**没有**结尾换行。
    用它拼变异脚本的替换块时，后面紧跟的代码会被粘到同一行 —— 本轮就踩了：
    替换块的 `Say 'HINT=...'` 和分支自己的 `exit 3` 被拼成一行，`exit 3` 进了字符串里，
    变异体于是「打印完 FAIL 继续往下跑」、退出码变成 0，测的其实是个坏脚本。
    修法：拼接前显式 `$block + "`n"`，并在写盘前断言 `(?m)^    exit 3$` 仍在（探针里已内置这条断言）。
31. **门禁只统计 `.md` / `.txt`，`reports\*.log` 的 CRLF 会溜过去**：`.gitattributes` 强制
    `* text=auto eol=lf`，工作副本里带 CRLF 的日志一旦入库，克隆出来就是 LF，
    **清单里的 sha16 与克隆内容对不上**。本轮提交前扫出 10 个 `reports\*.log` 带 CR
    （`b18-selftest-precheck.log` 一个就有 266 个 CR）。
    修法：入库前逐字节转成 LF（只去 CR，不动内容、不动 BOM），再刷清单。
    门禁阈值与白名单属**人工验收点**，本轮**未自行改** —— 是否把 `.log` 纳入统计留给人工裁决。
32. **git 推送要分清「代理断」还是「直连断」**：本机 git 全局配了 `http(s).proxy=http://127.0.0.1:7897`。
    走代理推 GitHub 报 `Recv failure: Connection was aborted`，而 `curl https://github.com` 直连返回 200
    ⇒ 是代理这条链断了，不是 GitHub 不可达（端口探测显示代理进程还在，是转发失败）。
    修法：用**单次命令覆盖** `git -c http.proxy= -c https.proxy= push origin main`
    （`ls-remote` 校验也要同样覆盖），**不要改用户全局 git config**。
    硬判据仍是 `ls-remote` 与 `rev-parse HEAD` 逐字相等。
