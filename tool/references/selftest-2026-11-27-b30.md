## 一、新能力：一次扫多本台账（只读）

`-Action migrate-hint` 新增 `-LedgerPaths <多值>`。仍是零写入路径：不取写锁、不建目录、不写临时文件。

- 输出：每本一行 `MIGRATE_SCAN path=… readable=true sha256=… stages=<n> max_stages=<raw> hints=<n>`，逐条 `MIGRATE_HINT path=<p> scope=…`，末行 `MIGRATE_SCAN_VERDICT ledgers=<n> hints=<n> unreadable=<n>`。
- 退出码：`hints>0` 或 `unreadable>0` ⇒ `3`，全干净 ⇒ `0`，参数非法 ⇒ `2`（复用既有码，不新增）。
- **不可读台账不中断**：只计入 `unreadable=` 并继续扫下一本。单台账模式完全保持原语义（`MIGRATE_STATE`/`MIGRATE_HINT`/`MIGRATE_VERDICT` 逐字不变，读不到仍 `LEDGER_FAIL` + exit 3）。
- 证据：`b30_batch_scan_judges_every_ledger` → `exit=3` + `MIGRATE_SCAN_VERDICT ledgers=3 hints=2 unreadable=1`；`b30_batch_scan_keeps_going_after_a_missing_ledger` → `scans=3 hints=2`（缺的那本没吃掉后两本）；`b30_clean_batch_exits_zero` → `exit=0` + `ledgers=1 hints=0 unreadable=0`。

实现上修掉一个真实入参缺陷：`-File` 调用里 `-LedgerPaths a,b` 会作为**单个** token 传进来，原先被整体当成一条路径。现在先 `Test-Path` 原始 token，只有当它确实不是已存在文件时才按 `,`/`;` 拆分，去空、去重、保序——含逗号的真实路径仍然可用。三条批量用例全部用「逗号拼接单 token」传参，正是踩在这个缺陷上。

## 二、身份键与计数（B30 加固）

1. `@($null).Count` 在 PS 7.7.0 实测为 `1`。台账缺 `sessions`/`notes` 时，`status`/`doctor` 会把「没有」报成 1。新增唯一入口 `Get-Elements`（`@(@($v) | Where-Object { $null -ne $_ })`），四个计数点全部改走它。证据：`b30_absent_trail_arrays_count_zero` → `ledgers=0 sessions=0 notes=0`。
2. **`sessions[]` 精确匹配**。原先前缀匹配，`sess-b30-alpha-long` 会被当成 `sess-b30-alpha` 已登记。改为：字符串 `Trim().Equals(…, OrdinalIgnoreCase)`；对象先比 `session_id` 再比 `id`；最后才是 `"id"` 整词令牌正则。证据：`b30_session_prefix_is_not_the_same_session` → 登记后 `count=2`，且 `LEDGER_SESSION_REGISTERED session=sess-b30-alpha stage=1 source=stage_field`。
3. **`stage_fields` 禁写身份键**。键为 `id`/`stage` ⇒ `LEDGER_FAIL reason=stage_fields_rewrites_identity stage_id=<id> key=<k> hint=identity_keys_are_not_stage_fields`，exit 2，且台账 sha 未变。证据：`b30_stage_fields_cannot_rewrite_identity`。
4. **`append_stage.id` 显式判型**。`[int]::TryParse` 失败 ⇒ `reason=append_stage_id_not_an_integer value=<v> hint=append_stage_id_is_the_number_the_stage_cap_counts`，exit 2（拒绝前先落 `LEDGER_CAS_OK`，拒绝后 sha 不变）。证据：`b30_non_numeric_append_stage_id_is_refused`（`value=7a`）。
5. **`bump_current_stage` 需要可解析的 `current_stage`**。失败 ⇒ `reason=current_stage_not_an_integer value=two hint=bump_current_stage_needs_a_numeric_current_stage_to_count_from`，exit 2。证据：`b30_bump_needs_a_numeric_current_stage`。
6. **阶段身份键三级回退：`id` → `stage` → `#<序号>`**。`LEDGER_CHAIN` 与启动器 cap 闸门渲染两处逐字同形，否则 B19-a 的交叉比对会红。证据（两条互补）：
   - `chain_status_legacy_stage_key_reads` → `cap_reached=true stages=1:done,2:done all_done=true open_stages=0`；
   - `chain_status_legacy_stage_key_agrees_with_launcher_stages` → `ledger=1:done,2:done launcher=1:done,2:done`，`…all_done ledger=true launcher=true`（启动器 `FAIL reason=chain_at_stage_cap` 行与台账一致）；
   - `chain_status_no_identity_key_reads` → `cap_reached=false stages=#0:done all_done=true open_stages=0`（无身份键阶段按序号定位，`#` 前缀明确表示「这不是 id」）。

## 五、本轮工具坑

- **判绿要回读三样**：`SUITE_END pass/fail`、包装层回显的 `EXIT=`、以及证据文件自身 sha/行数/CR。后台任务的 `succeeded` 只看最后一行命令的退出码，任何 suite 结果都会是 `0`。
- **`-EvidencePath` 与 `Tee-Object -FilePath` 不得同文件**（B29 已记，本轮沿用：stdout 只重定向到临时日志）。
- **`Select-String '^CASE_PASS'` 在证据文件里匹配不到**：证据每行带 `HH:mm:ss` 前缀。按用例名 grep，不要按行首。
- **同一轮里不要既改产品又改断言**：先在冻结树上跑出唯一失败项，再只动那一处，然后整轮重跑——否则分不清是新缺陷还是新断言的形状假设过窄。
