## 唯一红项与裁决

- 红项（run1）：`b35_known_turn_flag_is_passed` / `b35_known_turn_flag_is_not_warned`。
- 根因：**测试桩错，不是产品 bug**。桩用批处理 `echo --max-turns <turns>` 宣传该 flag；cmd.exe 把 `<turns` 当**输入重定向**，整条 echo 以「The syntax of the command is incorrect.」失败退出，help 输出里根本没有 `--max-turns`。装置于是**如实**走「未知 flag」分支（告警 + 丢弃该参数），两条断言一起红。
- 鉴别力（当场实测，非推断）：同一 PATH 前置下 `Get-Command claude` 解析到桩（`...\probe35-xxxx\claude.cmd`，CommandType=Application）⇒ 探针确实问的是桩；`echo --max-turns <turns>` 输出 1 行且是那句语法错误，`echo --max-turns turns` 输出 2 行且含 `--max-turns turns`。
- 修法（按用户偏好直接修，不发问卷）：桩改为不含尖括号的写法（`echo --max-turns turns`），并在桩旁写明原因。修后 run2 两条均 PASS，`--max-turns 3` 真实出现在 SPAWN_COMMAND 里。
- 红跑证据（覆盖前留档）：`reports\selftest-b35-run1-red.txt`，61826 B，sha256 `4E72C15E26FCDD008E74F553C37777D1714FBA366FA101AC431F91EAE365EE8A`。

## 本轮加的是什么（b35，17 条）

(a) **锁交接触发路径（13 条，此前零覆盖）**。`relay-spawn.ps1 -AdoptLock` 这条 `prespawn → adopt -Nonce → 子进程 → 失败时 release` 链路从未被任何测试执行过：case 27 只覆盖不带 `-AdoptLock` 的 `-Execute`，b25 只在锁脚本层测 `prespawn/verify`。b35 用桩 `claude.cmd` 走完整链路，断言：安装成功 → 取锁 → 起子进程 → `SPAWN_LOCK_PRE_ADOPTED`（nonce 16 hex）→ `LOCK_ADOPTED holder=<新> prev_holder=<旧>` → **子进程启动瞬间锁主人已是新 session**（桩在运行期把锁文件拷成 marker，测试据此判定「移交发生在子进程启动之前」）→ 运行后锁主人=新 session → permit 被消费且 `consumed_by`=新 session → 子进程失败 ⇒ exit=3 + `FAIL reason=runtime_run_failed` + `SPAWN_LOCK_RELEASED` + 锁文件不残留。

(b) **回合数上限的探测后降级（4 条）**。`-MaxTurns 3` 时装置先问 build 的 `--help`：认识 `--max-turns` 才下发（断言命令行含 `--max-turns 3` 且无告警），不认识则丢弃并告警 `WARN reason=max_turns_flag_unsupported flag=--max-turns requested=3 action=dropped hint=the_budget_cap_still_applies`（断言命令行不含该 flag 且有告警）。默认路径（`-MaxTurns=0`）零探测、零开销。
