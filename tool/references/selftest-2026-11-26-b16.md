# B16 门禁小结 —— 闸门兜底：跑到阶段上限却仍是 running 就拒绝起链（2026-11-26）

本批只做 B15 遗留 1：**补闸门兜底**。链跑完最后一个阶段、却没人把 `status` 翻成 `done` 时，
启动器过去会**再起一环**（计划外的 stage N+1）。现在直接拒绝。收尾按家规 `selftest → publish → refresh-manifest`。

## 1. 兜底判据为什么不是「next_session_id 为空」

B15 遗留条目原本的设想是「阶段全 done 且 `next_session_id` 为空 ⇒ 拒绝」。**这个判据不成立**：

- B13 真链终态证据 `tool\references\live-chain-b13-ledger-final.txt`：`status=blocked` / `current_stage=3` /
  `max_stages=2`，`next_session_id` **仍有值**（`4dcfed63-...`），收链时并没有被清空。
- `relay-ledger.ps1` 的 patch 逻辑**没有清空路径**：`next_session_id` 只在非空时写入，空串进不去。

⇒ 判据改成纯状态比较：**`status=running` 且 `current_stage >= max_stages`**。
「没有 `in_progress` 阶段」这一半由排在前面的 `stage_in_progress` 分支天然保证，半途崩溃仍走原分支。

## 3. 新增门禁用例（case 22，2 条断言）

| 断言 | 判据 | 鉴别力 |
|---|---|---|
| `gate_refuses_running_chain_at_stage_cap` | 夹具台账 `status=running` / `current_stage=2` / `max_stages=2` / 两阶段全 `done` / `next_session_id=$null` ⇒ `exit=3` + `FAIL reason=chain_at_stage_cap` | 去掉新分支就会放行起链 ⇒ 必红 |
| `gate_still_starts_below_stage_cap` | 同一夹具改 `current_stage=1`（stage 2 仍 `pending`）⇒ `exit=0`、**不含** `chain_at_stage_cap`、且输出 `DRYRUN skip=lock_acquire` | 判据若写成「有阶段全 done 就拒」或边界写错 ⇒ 必红；证明没把正常接力一起挡死 |

第二条是反向对照：没有它，「拒绝」可能只是把整条链全拒了，判据没有鉴别力。
