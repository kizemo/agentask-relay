# B23 小结：MiniMax Code 侧「接力任务排进 sigma-file-manager 项目」—— 项目按精确工作目录归档，装置让错配可见

本批处理一个现场问题：**在 MiniMax Code（MCode）里跑 filemanager 仓库的自动接力，链子会话被排进了侧栏项目
`sigma-file-manager`；并且「进入会话」看不到会话的归属项目。** 结论先给：

> **归属不是 bug，也不是「挂错项目」。MCode 的项目 = 工作目录的精确字符串键**（无包含映射）。
> 链的 cwd 是仓库根 `F:\soft\00selfmade\filemanager\sigma-file-manager`，所以它的会话**本来就应该**在这个项目下。
> 真正的问题是**两个不同目录的侧栏项目名字撞在一起**（外层容器 `filemanager` vs 仓库 `sigma-file-manager`），
> 用户按名字理解就成了「排错项目」；而「进入会话不显示归属项目」在数据层**无法复现**，属应用侧渲染问题。

责任划分：**数据层无错，链路无错；装置侧可做的是「让归属错配可见」**（B23 新增），**用户侧可做的是「把项目改名对齐」**。

---

## 1. 机制：MCode 的项目是精确工作目录键（只读实测）

运行时库 `E:\Users\Duanyi\.minimax\.minimax\v2\sqlite\runtime-state.sqlite`（3.6 GB，只读）：

- 表 `local_runtime_projects.workspace_dir` 上有唯一索引 `idx_local_runtime_projects_workspace_v1`；
- 触发器 `trg_local_runtime_project_session_insert_v5` 按 `project_workspace_dir` **精确匹配**，
  匹配不到就**自动建一行项目**。

⇒ **项目 = 精确工作目录**。传一个「包含关系」的上层目录**不会**命中下层目录的项目。

### 1.1 探针 A：`project` 不做包含映射

`session_create(project="F:\soft\00selfmade\agentask-relay\tool", ...)` ⇒ 新建项目行 **2577**，
会话 `mvs_5e04259f569d4fcd88b077ad37c25411`，其 `project_workspace_dir` = 那个**子目录**本身。
⇒ `project` 参数**只等于「在该目录里跑」**，不是「归属到上层项目」。

### 1.2 探针 B：`project` 与 `workspace_dir` 互斥（决定性）

`session_create(project="F:\soft\00selfmade\filemanager", workspace_dir="...\sigma-file-manager", ...)`
⇒ 运行时**直接拒绝**：`SESSION_CREATE_INVALID_ARGUMENT`「project 和 workspace_dir 只能填一个」，**零残留**。

⇒ 「cwd 在仓库根、归属外层项目」这条路径**不存在**。**唯一可行修法是应用层改名对齐**。

## 2. 现场事实（盘上回读）

| 项目 id | workspace_dir | 侧栏显示名 | 会话数 |
|---|---|---|---|
| 7 | `F:\soft\00selfmade\filemanager`（外层容器，**非** git 仓库） | `filemanager` | **409** |
| 2565 | `F:\soft\00selfmade\filemanager\sigma-file-manager`（**仓库根**） | `sigma-file-manager` | **3**（接力链 stage1/2/3） |

**结论：链的会话落在 2565（仓库根）是正确的**，因为链的 cwd 就是仓库根。

## 3. 用户的四个问题，逐条回答

1. **是否造成项目错误？** — **否**。项目归属由 cwd 决定，链的 cwd = 仓库根，归属正确。数据层
   `project_id` / `project_workspace_dir` 均正常。
2. **是否在其它目录生成了错误文件？** — **否**。递归普查：容器目录 `F:\soft\00selfmade\filemanager` 下**没有** `docs\`；
   全盘 `stage-*-inventory.md` 仅出现在合法仓库（filemanager 仓库 / practilog / rime_claude / agentask-relay examples 快照）。
   容器根有 **5 个散落产物**（合计 549564 B）属早期批次遗留，可清理。
3. **是否需要迁移？** — **不需要**。会话本身**不能换项目**（`project` 与 `workspace_dir` 互斥，见探针 B）；
   且归属本就正确，迁移只会制造新的错位。
4. **是否有垃圾文件要删？** — **有**：① 容器根 5 个散落产物；② `F:\soft\00selfmade\_relay-port-selftest`
   （14 文件 / 50432 B）、`_relay-port-adopt-test`（11 / 42703 B）、`_relay-port-realagents-test`（11 / 331121 B）；
   ③ `%TEMP%\relay-*` **44** 个目录 / 119093828 B（**删前必须排除正在跑的 `relay-port-selftest`**）；
   ④ MCode 侧栏垃圾项目 3 个（repo×2、probe-ws）+ 6 个会话。

## 4. 装置改动：让「归属错配」可见（B23）

`tool\templates\start-relay.ps1`（`device\start-relay.ps1` 同步为逐字副本）：

- 新增参数 `[string]$ExpectedHostProject = ''`；
- 新增 section 1d「host project key」：
  - 每次起链打 `INFO host_project_key exact_workspace_dir=<仓库根>`；
  - 期望项目（**参数优先**，其次 `docs\relay\host-project.txt`）≠ 仓库根时打
    `WARN host_project_mismatch expected=… actual_key=… reason=host_projects_are_keyed_by_exact_workspace_path hint=…`；
- **prompt 一个字未改**（mcode prompt 逐字不变式保持）；不改台账 schema、不改 `relay-runtime.json`。

期望值缺省时**不报**（零误报）。`docs\relay\host-project.txt` 是可选的落地写法（内容 = 期望的工作目录绝对路径）。

## 5. 门禁：新增 case 28（鉴别力：好样本 / 坏样本各跑一次）

`scripts\selftest.ps1` case 28 用一个**嵌套容器**夹具造出「仓库根 ≠ 期望项目」的相反样本：

| 样本 | 期望值 | 期望判据 | 断言 |
|---|---|---|---|
| 坏样本 | 父容器目录 | **必须**报 `host_project_mismatch`，且报出实际 key | `host_project_mismatch_reported` / `host_project_mismatch_names_the_key` / `host_project_mismatch_explains_the_rule` |
| 好样本 | 仓库根本身 | **不得**报 mismatch，只报 `INFO host_project_key` | `host_project_match_is_quiet` / `host_project_key_always_reported` |

另有 1 条安装器断言 `host_project_install_exit_zero`。本批共 **6 条**新断言，全部 `CASE_PASS`。

## 7. 坑

1. **MCode 的 `session_create` 真实 schema 只有** `content` / `agent_name` / `title` / `workspace_dir` / `model` / `location`
   —— `project` 只是 `workspace_dir` 的另一个写法，**二者互斥**。
2. **`workspace_dir` 必须传反斜杠绝对路径**，正斜杠会被静默丢弃。
3. **项目键是精确字符串**：想「挂到上层项目」在 MCode 里**做不到**，只能改名让用户看得懂。
4. **MCode 没有 `CLAUDE_CONFIG_DIR` 等价隔离手段** ⇒ 真链验证必然在用户级项目表里留条目，
   只能「验证后归档会话 + 移除项目」；这条要写进验证流程。
5. **`project_remove` / `project_archive_sessions` 必须用户明确同意**（skill 硬规则）：跳过的问卷、沉默、
   系统自动选项**都不算同意**。
6. **自测子进程零输出 + 非预期退出码 ⇒ 先怀疑环境，别急着改逻辑**：复现三次再定性。
