# B14 门禁小结 —— F6「台账会话流水」兜底（2026-11-26）

本批只做一件事：**把 B13 真链暴露的 F6（终态 `sessions=[]`）在台账闸门里修掉**，并按家规收尾顺序
`selftest → publish → refresh-manifest` 推进。F5（终态 `status=blocked`）本批**有意不改**，处理口径见
「F5 与下一批」一节。

## 1. F6 根因（不是「子环忘了写」，是装置缺兜底）

B13 真链终态台账里 `sessions=[]`，而 `stages[].session_id` 两环都有值。原因是**会话流水只写在散文里**：

- 协议 `AGENT-RELAY.md` 要求 patch 带 `sessions_append`（4 个意图）；
- 启动器生成的 prompt 的收尾规则只要求 **3 个意图**（`stage_done` / `bump_current_stage` / `next_session_id`），
  `sessions_append` 只在「可用键列表」里出现过，没被要求；
- 于是子环按 prompt 办事 ⇒ 台账里没有独立的会话流水。

结论：**光在 prompt 里加一句要求不够**（改了 prompt 就破 B10 的「mcode prompt 逐字不变」硬约束，
且任何运行时的子环都可能忘）。正解是让**闸门自己登记**：谁提交了 `stage_done`，闸门就把这一环的会话 ID
记进 `sessions[]`。散文要求因此降级成机制兜底。

**闸门的登记规则**（全部只追加，不改写、不删除）：

1. 会话 ID 取值优先级：`stages[N].session_id` → 台账里的 `next_session_id`（那正是当前在跑的那一环）→ 没有就**不登记**。
2. 去重：ID 已在 `sessions[]` 里（含「某条已含该 ID」的情形）就跳过 ⇒ 同环重跑幂等、协议里同时发
   `sessions_append` 也不重复。
3. 回显：`LEDGER_SESSION_REGISTERED session=… stage=… source=…` / `LEDGER_SESSION_ALREADY_REGISTERED session=…` /
   `LEDGER_SESSION_SKIPPED stage=… reason=no_session_id`（**没有来源就跳过，不编造 ID**）。

**为什么不碰 prompt**：F6 的修法刻意只动台账闸门，**一行 prompt 都没改** ⇒ B10 的
「未配置阶段的既有安装，mcode prompt 逐字不变」这条硬约束仍然成立（case 19 的
`b13_mcode_prompt_*` 四条断言原样通过即为证）。

## 5. F5 与下一批

### F5（终态 `status=blocked` 而非 `done`）—— 本批有意不改

口径按台账「遗留与下一批计划」处理：**需要人拍板**，不自行决定。现状与两处口径不一致：

- 装置自己的 `stop_conditions` 写着「`current_stage >= max_stages -> status=blocked`」⇒ 子环照章办事；
- 启动器的闸门另有 `status=done && current_stage >= max_stages` ⇒ `chain_exhausted` 判据。

⇒ 链跑完了却落字面 `blocked`（B13 真链实测：`blocked` / `current_stage=3` / `max_stages=2`）。

**本批新增的一条判断（值得下批先看）**：`stop_conditions` 出现在 `start-relay.ps1` 的**台账种子**里，
**不在 prompt 文本里**（种子在 292 行附近，prompt 块从 417 行才开始）⇒ 改「终态口径」存在一条
**不动 prompt** 的候选路径（改台账种子文案 ⇒ 子环按新文案置 `status=done`）。
但它会**改掉新链的 stop_conditions 语义**，且既有链的台账里仍是老文案 ⇒ 仍需人拍板，本批不实施。

## 6. 本批工具坑（新增）

1. **闸门类需求的默认修法是「加机制兜底」，不是「加一句要求」**：F6 的本质是散文要求没有机制，
   只在 prompt 里加要求会把同一个洞留在别的运行时上。
2. **回退取值要挑「当前在跑的那一环」**：台账 `next_session_id` 在提交前正好指向当前这一环
   （上一环写的，启动器为 CLI 首环写的）⇒ 可作会话 ID 的第二来源；注意读的是**提交前**的值。
3. **去重要按「包含」而不是「相等」**：协议里的 `sessions_append` 可能带别的上下文，按相等去重会漏。
4. **.md 行的缩进要用读到的原文**：`AGENT-RELAY.md` 用 **5 空格**缩进（4/6 都匹配不上），
   `old_string` 锚不准就改锚 ASCII 片段或改用脚本替换。
