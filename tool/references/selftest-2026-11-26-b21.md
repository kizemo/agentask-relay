# B21 小结：一次性验收器的日志不再自我覆盖 + 首跑 PASS 落盘留证

本批只补 B20 的一条遗留：**验收证据没有留在盘上**。B20 那次 `reports\b20-verify-finalize.ps1`
确实印过 `VERIFY_OK`，但脚本每次都把日志写到夹具根的**同一个固定文件名**，且开头先 `Remove-Item`，
于是紧接着的一次复跑（守卫轮，只印 `STALE_STATE`）把 25 条 PASS 整段截断覆盖 —— 证据只剩当轮会话输出，
会话一关就没了。本批做两件事：把日志改成**带序号、不覆盖**，并在**重建的夹具**上真跑一次，
让首跑 PASS 成为仓库里的原生文件。

---

## 1. 验收器改动：`reports\b20-verify-finalize.ps1`（8562 → 9487 B，纯 ASCII）

- 新增 `-Root` / `-ExpectPreSha` 两个参数。默认值仍指向 B20 那个已消耗的夹具与它的 pre-sha
  `29CB450E...`，因此**省略参数**跑，得到的还是 `STALE_STATE` + `exit 2`，不是 7 条红检查。
- 原先写死的 `$preSha = '29CB450E...'` 改为 `$preSha = $ExpectPreSha.ToUpperInvariant()`；
  不改这一行，`-ExpectPreSha` 传参就是空转，新夹具必被判陈旧。
- 日志改写到**脚本自己所在目录**（`reports\`），命名 `b20-verify-finalize-run<N>.log`，
  `N` = 现存最大序号 +1，用 `[IO.File]::Open(..., FileMode::CreateNew, ...)` 预先占位。
  `CreateNew` 的语义是「同名存在就抛异常」，所以**任何历史日志都不可能被截断**，包括并发重名。
- 日志第二行新增 `VERIFY_LOG=<绝对路径>`，以后拿到输出就能直接反查文件。
- 陈旧守卫的 `HINT=one_shot_verifier` 补上重建路径：`b20-e2e-setup.ps1` → `b21-rebuild-crash-shape.ps1`
  → 用它的 `PRE_SHA` 回喂 `-Root` / `-ExpectPreSha`。

文件不变量实测：`BYTES=9487 CR=0 NONASCII=0 BOM=False PARSE_ERRORS=0`。

## 2. 新装置：`reports\b21-rebuild-crash-shape.ps1`（7986 B，纯 ASCII）

接 `-Repo <夹具>\repo`，把 `b20-e2e-setup.ps1` 留下的空台账推进成 crash shape：

- **前置断言**：`running / current_stage=1 / max_stages=1 / stages=[] / next_session_id` 空，
  且 `goal` 逐字等于验收器要的字串；不符就 `REBUILD_PRECONDITION_MISMATCH` / `REBUILD_GOAL_MISMATCH` 并 `exit 2`，
  一个字节都不动（复用 B20 坑 38 的教训，不再把「形状不对」演成「产品红了」）。
- **写阶段物**：`docs\relay\stage-1-inventory.md`，逐行 `git ls-files` 的路径 + 字节数 + 总计，
  路径保持 git 正斜杠原样，写完立刻回读自查「每个 tracked 路径都在文里」。
- **两次台账提交**（都走 `-Action status` → `commit -DryRun` → 核对 dry-run 未写盘 → `commit -ExpectSha256`）：
  `{"append_stage":{"id":1,"title":"inventory tracked files","status":"pending"}}`，然后
  `{"stage_done":1,"bump_current_stage":true}`。
- **收尾断言**：盘上回读 `running / 2 / 1 / [1=done] / next_session_id 空 / goal 未变`，
  再让闸门 `-Action status` 自己说一遍 `status=running`，最后印 `FIXTURE_REPO=` / `PRE_SHA=` / `REBUILD_OK`。

三处刻意的设计，理由都写在脚本头注释里：

1. **分两次提交，不合并**。`relay-ledger.ps1` 先解析 `stage_done`（`:255`）再应用 `append_stage`（`:318`），
   一个补丁同时带两键必然 `stage_not_found`。这条是读源码定位的，未做合并包的实测。
2. **阶段物不入 git**。一旦 `git add` 了它，`git ls-files` 就会包含它自己，而验收器要求
   「文里出现每个 tracked 路径」—— 那时就得让它列出自己，清单口径反而自指。留未跟踪，两边判据都干净。
3. **不碰 `set_status`**。终态必须留给启动器的 `-AutoFinalize` 去翻，否则验收器第 2 段就无事可验。

## 4. 诚实边界：这是「重建夹具」，不是新的真链

B21 复证的是**启动器 `-AutoFinalize` 那段状态机在 crash shape 上仍然成立**，链路是
「真安装器 → 真启动器 → 人工按台账协议提交两次 → 真验收器」。它**没有**起新的 `session_create` 会话，
因此**不能**算作「真链复跑」。真链机制证据仍然只有 B20 那一条（`mvs_bbd188bdad554326b41db3872cb9754f`），
B20 §「未验证 / 遗留」#2（真链证机制 + 见证证措辞）**本批不关**。

## 6. 坑

1. **一次性脚本把日志写在夹具里 = 证据随夹具一起消失**。夹具在 `%TEMP%`，随时可删；
   验收记录必须写在仓库侧（`$PSScriptRoot`），并且**序号递增 + `CreateNew`**，否则一次复跑就覆盖首跑。
2. **「先删后写固定文件名」是自毁证据的标准姿势**。B20 的 25 条 PASS 就是这么没的；
   改法不是「记得别跑第二遍」，而是让第二遍**物理上写不进去**（同名抛异常 → 自动换下一个序号）。
3. **`stage_done` 与 `append_stage` 不能同包**。闸门先按 `stage_done` 找阶段、后按 `append_stage` 追加，
   顺序在 `relay-ledger.ps1:255` 与 `:318`；同包会以 `stage_not_found` 失败。
4. **`^FAIL ` 不等于检查失败**。启动器把自身的 `FAIL reason=...` 也写进同一条 stdout，
   验收器再把 stdout 原样抄进日志；判绿只看 `SUMMARY fail=0` 与 `VERIFY_OK`。
5. **`-ExpectPreSha` 这类参数要真的接到判断上**。只加参数、不改写死的那行局部变量，
   表现是「传了没反应」，比不传更难查 —— 本批收尾前就踩到过，已改成 `$ExpectPreSha.ToUpperInvariant()`。
