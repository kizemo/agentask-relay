- **只读契约**：`-Action doctor` 全程不调用 `Enter-WriterLock`、不建目录、不写临时文件（连 `Move-Item` 落盘都没有），只在 stdout 打结果。`b28_doctor_writes_no_byte` / `b28_doctor_takes_no_lock_and_leaves_no_temp` / `b28_reporting_writes_nothing` 三条守着这一点。
- **输出形状**：首行 `DOCTOR_STATE path=… sha256=… status=… current_stage=… max_stages=… stages=N sessions=N notes=N`（`sha256` 就是它真正读到的那个，`b28_doctor_reports_the_sha_it_read` 守），中间逐条 `DANGLING …`，末行 `DOCTOR_VERDICT ok findings=0`（exit 0）或 `DOCTOR_VERDICT dangling findings=<n>`（exit 3）。
- **检查项（只报盘上可判的自相矛盾）**：`status` 不在 `running|pending|done|blocked`；`current_stage` 非整数；`current_stage > max_stages`（`reason=beyond_stage_cap`）；`current_stage` 在 `stages[]` 里找不到（`stage_missing`，**`stages` 为空时跳过**，否则启动器刚自举的新台账会被误报）；同一 stage id 重复（`reason=duplicate_stage_id`，只报一次并带 `count=<n>`）；`next_session_id` 非空但 `status≠running`（`reason=dead_pointer`）；`status=blocked` 却没有 `blocked_on`；`status=done` 却还有未完成阶段（`reason=open_stages`）。
- **身份键兼容（真实数据逼出来的修补）**：stage 身份键优先取 `id`，缺失时回退老台账使用的 `stage`；两者都没有时逐个报 `stage_index=<i> reason=stage_id_missing`，且不计入重复统计。详见下节。
- **它不猜**：「这个 session 是否已被归档」要先问宿主，doctor 一律不出 `session_archived` 之类结论，避免把猜测写成判据。
- **退出码复用既有契约**：`0` 干净 / `3` 有 findings（与「台账缺失或不可解析」同码）/ `2` 参数非法，不新增码，免得调用方判读口径分裂。

## 为什么多了「身份键兼容」：拿真实历史台账巡检出来的假阳性

`doctor` 首版只读 `stages[i].id`。对案例仓库的历史快照做**只读**巡检（`examples\practilog\docs\relay.json`，盘上 `sha256=67E1E5886874…`，未被改动）得到：

- 首版：`DANGLING current_stage=6 stage_missing=6` + 五行 `DANGLING stage_id= reason=duplicate_stage_id`（空 id 互相「重复」）+ `DOCTOR_VERDICT dangling findings=6` / `EXIT=3`
- 订正后：`DOCTOR_STATE … status=done current_stage=6 max_stages=6 stages=6 sessions=7 notes=1` + `DOCTOR_VERDICT ok findings=0` / `EXIT=0`，且巡检前后台账 `sha256` 同为 `67E1E5886874`

根因：该台账 `stages[]` 的元素键是 `stage`（`stage=1..6`），没有 `id`。首版取 `id` 得空串，于是既把 `current_stage=6` 误报成缺失，又对每个「无名」阶段各打一行重复。
这条属于「根因明确 + 代价可逆 + 有断言兜底」的修补，直接改：键回退 `id → stage`；两者都缺时单报 `stage_id_missing`（按序号定位，不参与重复判定）；重复组归并为一行并带 `count`。
配套断言：`b28_stage_keyed_ledger_is_not_dangling`（`stage` 键台账 `exit=0`、`findings=0`）、`b28_stage_key_counts_as_the_current_stage`（不再出 `stage_missing`）、`b28_stage_without_any_key_is_reported_once`（两行 `stage_id_missing`、`hits=2`）、`b28_unnamed_stages_are_not_duplicates`（无名阶段不进 `duplicate_stage_id`）、`b28_duplicate_is_reported_once_with_count`（`count=2` 且只出现一次）。

## 本轮工具坑

- 冒烟阶段自查抓到一处自造 bug：判 `stage_missing` 时用 `[int]::TryParse(...,[ref]$curNum)` 把 `current_stage` 覆盖掉了，已改为字符串比较。改完两处夹具仍复现 `findings=3`，`clean` 仍 `exit 0`。
- **首版绿盘不等于工具可用**：`pass=397 fail=0` 时 doctor 对真实历史台账会报 6 条假 findings。只跑自造夹具发现不了这类缺陷，必须拿真实台账做一次只读巡检。巡检是只读的，`sha256` 前后同值即为证。
- `Get-Content <ledger> | ConvertFrom-Json` 后直接打印 `stages` 会把整段 note 正文吐进对话（一次就吃掉大量上下文）；只看键名，用 `.PSObject.Properties.Name`。
- 临时目录夹具不能用 `Remove-Item` 清（本地安全策略直接拒绝整条命令），只能留原地或走 `mavis-trash`。
- 判活只能看重定向控制台文件的行数/字节增长，`| Select-Object -Last N` 会缓冲到进程结束才回显。
